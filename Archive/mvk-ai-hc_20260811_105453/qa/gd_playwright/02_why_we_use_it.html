Why We Use It

Plain A login form or a chat send button can look correct in isolation and still be broken end to end — the wrong API call, a missing redirect, a guard that doesn't fire. Browser-level testing catches exactly that class of bug, by actually driving the app the way a person would.
  • Tests the real user journey, not just units. A test doesn't just check that a function returns the right value — it fills in a login form, clicks submit, and asserts on what actually renders next.
  • Exercises real backends where it matters. Most of this suite runs against the actual HC.AI.Identity.Api (and, for one test, the actual HC.AI.MAPI + Ollama) — not a stand-in that could quietly drift from what the real backend does.
  • Catches route-guard regressions. Several tests exist purely to confirm an unauthenticated visitor gets redirected away from a protected page — exactly the kind of thing that's easy to silently break while refactoring.
