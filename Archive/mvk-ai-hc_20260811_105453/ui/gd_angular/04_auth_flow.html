Auth Flow

Plain Logging in is real, not a demo — it calls the actual Identity API, stores a genuine JWT, and that token rides along automatically on every later request. (The Identity & Authentication section covers the backend half of this in full; this page covers the Angular side only.)

Token storage

login(email: string, password: string): Observable<AuthResult> { return this.http.post<LoginResponseDto>('/api/users/login', body).pipe( map((res) => { const user: AuthUser = { id: ..., fullName: res.fullName, email: res.email, persona: personaFromRoleId(res.roleId) }; this.setSession(user, res.token); return { isNotValid: false, message: '', user }; }) ); } private setSession(user: AuthUser, token: string): void { this.currentUser.set(user); localStorage.setItem(STORAGE_KEY, JSON.stringify({ user, token })); }

Attaching the token to every request

export const authInterceptor: HttpInterceptorFn = (req, next) => { if (!req.url.startsWith('/api')) return next(req); const token = inject(AuthService).getToken(); if (!token) return next(req); return next(req.clone({ setHeaders: { Authorization: `Bearer ${token}` } })); };

Protecting routes

export const authGuard: CanActivateFn = () => { const auth = inject(AuthService); return auth.isLoggedIn() ? true : inject(Router).createUrlTree(['/login']); };

A caveat left directly in the code, worth surfacing rather than hiding: the JWT is stored in localStorage because the API returns it in the response body rather than a Set-Cookie header — the code comment flags this explicitly as "the pragmatic default forced by the API's current shape, not a considered final answer," with httpOnly-cookie storage noted as needing an architecture decision.
