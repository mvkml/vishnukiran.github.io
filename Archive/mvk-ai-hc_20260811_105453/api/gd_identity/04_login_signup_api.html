Login & Signup API

Plain A small, focused set of endpoints handles the whole account lifecycle — creating an account, logging in, and recovering a forgotten password — all under one consistent route prefix.
EndpointReturns
POST /api/users/signupThe created user (no token — user must log in separately)
POST /api/users/loginThe signed JWT, in the response body, on success (200); 401/400 on failure
POST /api/users/forgot-passwordConfirmation response
POST /api/users/reset-passwordConfirmation response
GET /api/users/rolesThe list of available roles (Doctor/Patient)
Plain Logging in is the moment the token is actually issued — the response the browser gets back from /login contains the token, ready to be attached to every future request.

These endpoints are intentionally open (no [Authorize] required to reach them) — that's expected, since a user isn't authenticated yet at the point they're trying to log in or sign up.
