Overview — The Identity Model

Plain Rather than every backend service handling its own logins, one dedicated service — the Identity API — is the single source of truth for "who is this user." It issues a signed token on successful login, and every other part of the platform trusts that token instead of re-checking credentials itself.
Technical Authentication is centralized in HC.AI.Identity.Api, which owns the Users/Roles tables and issues JSON Web Tokens (JWTs) on login. Any other API that wants to trust a caller's identity validates that same token rather than implementing its own login — this project's AI assistant API (HC.AI.MAPI) is set up to do exactly this.
Doctor/Patient logs in via Angular → HC.AI.Identity.Api validates credentials, issues a signed JWT → Angular stores the token and attaches it to every subsequent API call → Any API that receives the token (Identity.Api itself, and HC.AI.MAPI) validates its signature/issuer/audience/expiry before trusting the caller's identity
