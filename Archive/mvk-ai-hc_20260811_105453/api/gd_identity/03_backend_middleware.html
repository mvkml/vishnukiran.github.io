Backend Middleware

Plain Every request that comes into the API passes through a fixed sequence of checks before it reaches any actual business logic — one of those checks is "does this request carry a valid, unexpired token from a source we trust."
Technical Configured in HC.AI.Identity.Api/Program.cs using ASP.NET Core's built-in JWT Bearer authentication handler: 
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options => {
        options.TokenValidationParameters = new TokenValidationParameters {
            ValidateIssuer = true,
            ValidIssuer = jwtSettings.Issuer,
            ValidateAudience = true,
            ValidAudience = jwtSettings.Audience,
            ValidateIssuerSigningKey = true,
            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtSettings.SecretKey)),
            ValidateLifetime = true,
            ClockSkew = TimeSpan.Zero,
        };
    });
builder.Services.AddAuthorization();

And the middleware pipeline order that applies it to every request:

app.UseCors("AllowAngularDev"); app.UseHttpsRedirection(); app.UseAuthentication(); // validates the token, if one is present app.UseAuthorization(); // enforces [Authorize] on protected endpoints app.MapControllers();

What "strict" validation means here

Four things are checked on every token, all set to true: the issuer matches, the audience matches, the signature matches the shared secret key, and the token hasn't expired. ClockSkew is explicitly set to zero — there's no default grace period (ASP.NET Core normally allows 5 minutes) for a token that's just expired.

CORS

A single named policy, "AllowAngularDev", allows requests only from http://localhost:4201. This is a local development origin — a production deployment would need its real origin added here.
