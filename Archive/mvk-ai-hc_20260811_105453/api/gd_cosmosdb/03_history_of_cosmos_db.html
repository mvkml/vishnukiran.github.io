History of Cosmos DB

Plain Cosmos DB didn't start out as an AI database — it was built years before generative AI made vector search a mainstream requirement. Its recent vector-search additions are a new capability layered onto a much older, battle-tested foundation, not a ground-up rebuild.
PeriodMilestone
2014Launched as Azure DocumentDB — a managed JSON document database, Microsoft's first entry into the NoSQL document-database space
2017Relaunched and rebranded as Azure Cosmos DB — the headline change was global distribution as a first-class, built-in feature, plus multi-model support (adding Graph and Table APIs, and MongoDB API compatibility, alongside the original document model)
Following yearsA serverless consumption mode was added (pay per operation instead of provisioning throughput), along with a free tier and broader API compatibility (including a PostgreSQL-compatible option)
More recentlyVector search support was added to the NoSQL API — native vector indexing and similarity-search query operators, aimed directly at Retrieval-Augmented Generation and other AI-search workloads
Why this matters here: the vector-search capability this project intends to use (see Vector Database Capabilities) is one of Cosmos DB's newest features, added specifically to make it viable as a RAG store — it isn't a separate, bolted-on vector database product.
