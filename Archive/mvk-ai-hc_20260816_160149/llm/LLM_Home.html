Large Language Models

How Healthcare Co-Pilot Studio uses LLMs as a controlled reasoning and communication layer, not as an unchecked source of healthcare truth.

Staging Draft LLM Section Product & Technical Summary

1. Why LLMs Matter Here

Plain The LLM gives doctors and patients a natural way to ask questions. Instead of forcing users through forms, filters, SQL, or Swagger screens, the system lets them ask in plain language and then turns that request into a controlled backend flow.
Technical The LLM is deliberately treated as an interpreter and answer composer. It is not allowed to freely invent patient facts or execute raw SQL. Healthcare data access is routed through application guardrails, persona rules, and database-backed configuration.

2. Current LLM Architecture

01
Doctor / Patient Natural-Language Question
The workflow starts with a healthcare question written in everyday language.
02
Persona-Specific Angular Chat UI
The UI captures the question and carries authenticated Doctor or Patient context.
03
ASP.NET Core AI Assistant API
The API receives the request, validates the boundary, and starts the assistant workflow.
04
Semantic Kernel Orchestration Layer
Semantic Kernel coordinates prompt preparation, model connection, and execution flow.
05
Persona & Model Resolution
The platform selects the appropriate Doctor or Patient model/configuration path.
06
Ollama Local LLM Runtime
The selected local model generates language output inside the controlled runtime.
07
Guardrail & Grounding Layer
The system prevents unsafe free-form data access and prepares approved context.
08
SQL Server / Configured Data Sources
Real data, persona rules, model configuration, and allow-list metadata supply the source of truth.
09
Controlled Answer Composition
The final answer is composed from approved context instead of unsupported model assumptions.
10
Angular Chat UI Response
The response is returned to the Doctor or Patient in the chat experience.

4. Product Value

Business Value This project demonstrates that LLMs can be introduced into a healthcare workflow with clear boundaries: local model runtime, persona-aware behavior, backend orchestration, testing, and guardrails that keep the model from becoming the system of record.
Technical Strength The important engineering decision is separation of responsibility. Angular owns the persona UI, ASP.NET Core owns the API boundary, Semantic Kernel owns orchestration, Ollama owns model generation, SQL Server owns configuration and governed data access, and Playwright proves at least one real end-to-end LLM path.
