Doctor Persona Multi-Agent Design Patterns

Design patterns for handling doctor requests that may contain appointments, patient details, medications, insurance, claims, clinical documentation, and laboratory needs in one message.

Key decision: the classifier must support multiple classifications for one doctor request. The request should not be forced into only one agent when the sentence clearly asks for several healthcare domains.

Pattern Titles

1. Router Agent Pattern

Directs the request into the multi-agent workflow.
2. Multi-Intent Classification Pattern

Finds all matching domains in one doctor request.
3. Planner / Orchestrator Pattern

Plans which agents should run and in what order.
4. Fan-Out / Fan-In Agent Pattern

Runs multiple specialist agents and merges their outputs.
5. Supervisor Agent Pattern

Monitors routing, quality, failures, and escalation.
6. Tool-Using Specialist Agent Pattern

Lets each domain agent call approved APIs, MCP tools, or stored procedures.
7. Shared Context / Memory Pattern

Shares doctor, patient, session, and prior-chat context across agents.
8. Human-in-the-Loop Escalation Pattern

Escalates risky, incomplete, or policy-sensitive cases for review.
