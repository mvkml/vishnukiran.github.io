Router Agent Pattern

The first agent boundary that receives a doctor request and decides whether it should enter the normal answer flow, multi-agent flow, or an escalation path.

Purpose: protect the system from sending every request directly to a specialist. The router checks persona, request shape, safety boundaries, and whether the request needs classification.

How It Works

StepResponsibility
ReceiveAccept the doctor message, session id, logged-in user, and persona context.
GuardConfirm the request belongs to the Doctor persona and respects system boundaries.
RouteSend domain questions to classification, simple greetings to direct response, and risky requests to escalation.

Healthcare Example

A doctor asks for today's appointments and the medication status for one patient. The router identifies this as a healthcare domain request and sends it to multi-intent classification.
