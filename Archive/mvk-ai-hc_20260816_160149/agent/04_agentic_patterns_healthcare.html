Agentic Patterns In Healthcare Co-Pilot Studio

Current and planned agent patterns used across the Healthcare Co-Pilot Studio workflow.

Current position: Memory Agent and Tool-Using Agent are already implemented in the Doctor/Provider copilot. The agent stores and replays chat history through LLMChatHistory, calls MCP tools for healthcare data, and streams responses to Angular through Server-Sent Events.

Coverage Summary

Memory AgentCovered

Conversation turns are persisted in dbo.LLMChatHistory and replayed by SessionId and UserId.

Tool-Using AgentCovered

Provider Agent consumes MCP tools; appointment answers come from stored-procedure-backed tool calls.

Streaming AgentCovered

Doctor responses, progress, and errors are streamed to Angular using SSE.

Loop AgentPrototype

MVK Loop Agent demonstrates bounded repeated execution for R&D and controlled automation.

Reflection AgentPlanned

QA issues will trigger context replay and prompt/tool/model correction recommendations.

Validation AgentPlanned

Validates answer quality, grounding, safety, completeness, and business rule alignment.

Supervisor AgentFuture

Routes issues or tasks to validation, reflection, SQL, UI, QA, or human approval.

Current Runtime Flow

StepWhat HappensPattern
1Doctor sends a question from Angular with a conversation SessionId.Memory
2Provider Agent rebuilds prior context from LLMChatHistory.Memory Agent
3Agent connects to MCP tool hosts and registers tools in Semantic Kernel.Tool-Using Agent
4Model decides whether to call appointment/patient tools.Tool-Using Agent
5Tool layer reaches SQL through usp_Tool_* stored procedures.Tool Layer
6Final answer, status, and errors are sent back through SSE.Streaming Agent

QA Reflection Flow

  1. QA reviews the streamed Doctor copilot response.
  2. QA identifies an issue and submits severity, issue description, original prompt, and observed response.
  3. QA Validation REST API sends the case to the Reflection Agent.
  4. Reflection Agent checks prompt context, tool output, system prompt, and model configuration.
  5. Reflection Agent identifies root cause: prompt gap, tool instruction issue, model configuration issue, missing grounding, or unsafe response.
  6. Correction is recommended or applied with human approval for risky changes.

Validation vs Reflection vs Supervisor

PatternMain QuestionOutput
Validation AgentDid the answer pass quality, safety, grounding, and business rules?Pass/fail, score, category, evidence.
Reflection AgentWhy did it fail, and how should the agent improve?Root cause, prompt/config/tool correction, remediation plan.
Supervisor AgentWho should handle this issue next?Route to validation, reflection, SQL, Angular, QA, or human approval.

Architecture Summary

Healthcare Co-Pilot Studio currently implements Memory Agent and Tool-Using Agent patterns in the Doctor/Provider copilot. Memory is persisted through LLMChatHistory using session-based replay, and tool usage is implemented through MCP tools backed by stored procedures. The loop-agent console demonstrates controlled autonomous execution. The next business enhancement is a QA-driven Reflection and Validation workflow where QA can flag an issue and an agent can re-evaluate the prompt, tool output, system prompt, and model configuration to recommend or apply corrections.
