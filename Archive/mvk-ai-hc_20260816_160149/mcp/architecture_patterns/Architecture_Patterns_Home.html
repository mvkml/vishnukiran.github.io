MCP Architecture Patterns

The technical architecture vocabulary behind ADR004: how segregated MCP hosts can stay secure, understandable, and operable as the platform grows.

ADR004 Expansion Planned Architecture 2026-07-29
Current status: these pages document the architecture direction for future MCP growth. Today's HC.AI.MCP implementation still has one active tool path. The patterns below explain how the system should evolve once OP, ICU, Emergency, and other domain-specific MCP hosts exist.

Technical Architecture Summary

Architecture PointDecision
Trust boundaryTool visibility should be enforced by MCP host boundaries, not client-side filtering.
Domain splitFuture patient categories should map to bounded contexts such as OP, ICU, and Emergency.
Shared codeThin host projects can reuse EF, Repository, BL, validation, and model libraries.
Agent viewA gateway, BFF, or aggregation layer can give one agent a coherent view across approved hosts.
Operational modelEach host can have independent security, deployment cadence, scaling, and failure isolation.
