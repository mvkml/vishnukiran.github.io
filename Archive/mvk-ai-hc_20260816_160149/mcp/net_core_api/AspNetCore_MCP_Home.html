NuGet Packages

Package View The API project uses two important NuGet packages at the host level. One supports normal REST API documentation and testing. The other is the package that makes the ASP.NET Core service MCP-capable.
PackageVersionTypeRole And Responsibility
Swashbuckle.AspNetCore 6.4.0 ASP.NET Core REST API support Generates Swagger/OpenAPI metadata and Swagger UI for the REST controller surface, including api/PatientChart. This is useful for developer testing, QA verification, and client demos because the HTTP API can be inspected and called without an MCP client.
ModelContextProtocol.AspNetCore 1.4.1 MCP-specific Adds MCP server hosting support to ASP.NET Core. This package provides the extension methods used in Program.cs: AddMcpServer(), WithHttpTransport(), WithToolsFromAssembly(), and MapMcp(). It is the key package that allows this web API host to expose MCP tools for AI-agent access.
Architecture takeaway: Swashbuckle.AspNetCore serves the human and REST integration side of the service. ModelContextProtocol.AspNetCore serves the AI-agent tool integration side. Keeping both in the same ASP.NET Core host lets the team validate healthcare capabilities through REST while progressively exposing the same governed capability through MCP.

Program.cs Explained

Architecture View The ASP.NET Core MCP host is built in two layers. The first layer is normal ASP.NET Core REST API infrastructure: controllers, Swagger, dependency injection, EF Core, and middleware. The second layer is MCP-specific: registering an MCP server, enabling HTTP transport, loading MCP tools from an assembly, and mapping the MCP endpoint.
Program.cs Line / BlockTypeWhat It DoesWhy It Matters
var builder = WebApplication.CreateBuilder(args); ASP.NET Core Creates the application builder and loads configuration, logging, dependency injection, and hosting defaults. This is the standard starting point for a modern minimal-hosting ASP.NET Core API.
builder.Services.AddControllers(); ASP.NET Core REST Registers MVC controller support so classes like PatientChartController can handle HTTP requests. This enables the REST testing path: POST api/PatientChart.
AddEndpointsApiExplorer() and AddSwaggerGen() ASP.NET Core REST Adds API metadata and Swagger/OpenAPI generation for developer inspection and manual testing. Useful for client demos and QA because the REST endpoint can be inspected without an MCP client.
AddDbContext<McpDbContext>(...UseSqlServer(...)) Application data access Registers EF Core with SQL Server using the McpDb connection string. This connects the MCP host to the governed healthcare data layer and stored procedure execution path.
AddScoped<IPatientDetailsRepository, PatientDetailsRepository>() Application service Registers the patient details repository for request-scoped dependency injection. Follows the same layered pattern used across the solution, even when a capability is not the main focus of the page.
AddScoped<IPatientChartRepository, PatientChartRepository>() Application service Registers the repository that calls dbo.usp_ExecuteHealthcareQuery. This is the actual guarded data-access boundary behind the current PatientChart capability.
AddScoped<IPatientChartBL, PatientChartBL>() Application service Registers the business layer used between the service orchestration layer and repository layer. Keeps business coordination separate from controller, MCP transport, and EF implementation details.
AddScoped<IPatientChartValidationUtility, PatientChartValidationUtility>() Application guardrail Registers validation for RootTable, filter count, max record limits, and sort direction. Prevents malformed or oversized tool/API requests from reaching SQL first.
AddScoped<IPatientChartMapper, PatientChartMapper>() Application mapping Maps the incoming request model into the internal item shape used by BL and repository layers. Keeps external API/MCP request shape separate from internal execution shape.
AddScoped<IPatientChartResponseMapper, PatientChartResponseMapper>() Application mapping Builds the outgoing response from the processed model and repository result. Gives REST and future MCP tool calls a clean, consistent result contract.
AddScoped<IPatientChartService, PatientChartService>() Application orchestration Registers the service that coordinates request mapping, business-layer execution, and response mapping. This becomes the reusable core for both REST controller calls and future MCP tool calls.
builder.Services.AddMcpServer() MCP-specific Registers the MCP server components in ASP.NET Core dependency injection. This is the main switch that turns the ASP.NET Core host into an MCP-capable server.
.WithHttpTransport() MCP-specific Configures MCP communication over HTTP transport. Allows MCP clients/agents to connect to this service through a web-hosted protocol endpoint.
.WithToolsFromAssembly() MCP-specific Scans the configured assembly for MCP tool definitions. This is where future callable tools, such as a PatientChart MCP tool, become discoverable to an AI client.
var app = builder.Build(); ASP.NET Core Builds the configured web application pipeline. After this point, service registrations are turned into the runnable application.
UseSwagger() and UseSwaggerUI() ASP.NET Core REST Enables Swagger UI only in development. Keeps the developer/demo inspection surface available locally without treating it as the production AI boundary.
app.UseHttpsRedirection(); ASP.NET Core Redirects HTTP requests to HTTPS when the host supports it. Standard web API security hygiene.
app.UseAuthorization(); ASP.NET Core security Adds authorization middleware to the pipeline. Prepares the host for secured endpoints, although policy/auth configuration still needs to be completed for production-grade MCP access.
app.MapControllers(); ASP.NET Core REST Maps controller routes such as api/PatientChart. This exposes the REST API surface for testing and non-agent integration.
app.MapMcp(); MCP-specific Maps the MCP endpoint into the ASP.NET Core request pipeline. This exposes the MCP protocol surface that an AI client can connect to.
app.Run(); ASP.NET Core Starts the web application. Runs both surfaces hosted by this application: REST controllers and the MCP endpoint.

What Is MCP And What Is Regular REST?

CategoryItemsMeaning
Regular ASP.NET Core REST APIAddControllers, AddSwaggerGen, MapControllers, Swagger UISupports normal API development, manual testing, QA, and frontend/service clients.
Shared application architectureEF Core, repositories, BL, services, validation utilities, mappersBusiness logic reused by REST and future MCP tool calls.
MCP-specificAddMcpServer, WithHttpTransport, WithToolsFromAssembly, MapMcpTurns the API host into a Model Context Protocol server for AI-agent tool access.

Architecture Flow

AI agent or test client -> ASP.NET Core API / MCP host -> PatientChartController or future MCP tool -> PatientChartValidationUtility -> PatientChartService -> PatientChartMapper -> PatientChartBL -> PatientChartRepository -> McpDbContext -> dbo.usp_ExecuteHealthcareQuery -> PatientChartResponse
Honest status: the ASP.NET Core service is real and the MCP server is wired. The current proven healthcare capability is exposed through the REST controller. The next architecture step is to expose the same PatientChart capability as an explicit MCP tool from HC.AI.MCP.Tools, while reusing the same validation and service pipeline.
