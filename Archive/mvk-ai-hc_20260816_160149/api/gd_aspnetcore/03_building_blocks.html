Building Blocks

Plain Every API starts the same way: register what the app needs (database, security, business services), configure how requests get handled, then start listening. Inside, each request is routed to a small, focused method that delegates the real work down through clear layers rather than doing everything itself.

The minimal-hosting Program.cs shape

Consistent across all four APIs — register services, then configure the pipeline, then run. Representative example (HC.AI.Identity.Api, trimmed):

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

builder.Services.AddDbContext<AiHrDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("AiHrDb")));

builder.Services.AddScoped<IUserRepository, UserRepository>();
builder.Services.AddScoped<IUserBL, UserBL>();

var jwtSettings = builder.Configuration.GetSection("Jwt").Get<JwtSettings>()
    ?? throw new InvalidOperationException("Jwt configuration section is missing.");
builder.Services.AddSingleton(jwtSettings);
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options => { /* validation parameters */ });

var app = builder.Build();
if (app.Environment.IsDevelopment()) { app.UseSwagger(); app.UseSwaggerUI(); }
app.UseCors("AllowAngularDev");
app.UseHttpsRedirection();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
app.Run();

Controllers

Traditional MVC-style controllers, not the newer Minimal-API lambda-endpoint style. Dependencies come in through the constructor — the controller itself has no business logic, only routing and translating results into HTTP responses:

[ApiController]
[Route("api/users")]
public class UsersController : ControllerBase
{
    private readonly IUserValidationService _validation;
    private readonly IUserBL _userBL;
    private readonly IRoleRepository _roleRepository;

    // ... constructor injection ...

    [HttpPost("login")]
    public async Task<IActionResult> Login(LoginRequest request)
    {
        // validate -> call BL -> return Ok/Unauthorized/BadRequest
    }
}

Controller → BL → Repository → EF

Every domain follows the same layering, registered explicitly in Program.cs via AddScoped<IX, X>(): a Controller calls a Business Logic (BL) interface, the BL calls a Repository interface, and the Repository talks to the EF Core DbContext. This is most visible in AI.HealthCare.Patient.API, which registers roughly 70 services this way across its ~19 domain entities (Patients, Encounters, Conditions, Claims, etc.) — each entity gets its own Mapper, Repository, BL, and Validation Service.
