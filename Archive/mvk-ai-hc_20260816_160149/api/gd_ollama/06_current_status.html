Cold-start behavior — worth knowing before a live demo: Ollama has to load a model into memory before it can generate anything. If hc-doctor-executor:latest or hc-patient-executor:1.1 hasn't been called recently, that first request after idle time is measurably slower — observed at roughly 91–110 seconds for a single short message, versus about 18.5 seconds once the model is already warm. Doctor and Patient use different models, so each persona's first message in a session can hit this independently.

KernalFactory's HTTP client currently uses .NET's default 100-second timeout, which the observed worst case can exceed — meaning a cold-start request can occasionally be canceled outright rather than just arrive slowly. Tracked as BUG-001, still open. Two fixes are under consideration, neither shipped yet: raising the timeout past the observed worst case, or moving to a streamed response (PB045) so the reply appears token-by-token instead of arriving as one blocking call. If this is seen live, it's expected behavior for locally-hosted, on-demand LLM serving — not an environment fault.
Real config issue worth flagging: in appsettings.json, the FBDoctorExecutor fallback section's Model value is hc-patient-executor:1.1 — a Patient model configured under a Doctor fallback key. It reads as a copy-paste mistake rather than an intentional choice, and only takes effect on the rare no-authenticated-user edge case, but it's exactly what's checked into source control today.
