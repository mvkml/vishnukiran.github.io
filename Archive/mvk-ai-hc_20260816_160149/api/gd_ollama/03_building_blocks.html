How the app connects to it

The base URL is bound once from configuration and reused everywhere — never a literal string in business logic:

// appsettings.json "Ollama": { "Provider": "Ollama", "BaseUrl": "http://localhost:11434", "Model": "qwen2.5:7b" } // OllamaOptions.cs public class OllamaOptions { public string BaseUrl { get; set; } = "http://localhost:11434"; public string Model { get; set; } = "qwen2.5:7b"; } // Program.cs — a typed HttpClient built straight from that config builder.Services.AddHttpClient<IOllamaClient, OllamaClient>((sp, client) => { var options = sp.GetRequiredService<IOptions<OllamaOptions>>().Value; client.BaseAddress = new Uri(options.BaseUrl); });

That same configured base URL is what Semantic Kernel's KernalFactory also points at when it builds an Ollama chat-completion connector — one server, reached two different ways depending on which endpoint handled the request (see the Semantic Kernel section for the orchestrated path, and Current Status here for the direct-HTTP one).
