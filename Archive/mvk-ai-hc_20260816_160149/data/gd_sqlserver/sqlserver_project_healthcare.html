Roles Table

dbo.Roles is the authentication role lookup table. It stores the account-level role assigned to a user, such as Doctor, Patient, QA, DEV, AgentDev, and AgentQA.

This table is different from dbo.PersonaType. Roles answers "what account role does this user have?" while PersonaType answers "which LLM execution persona should be used?" The bridge between those concepts is dbo.PersonaMapper.

Stored Procedure

The main stored procedure connected to dbo.Roles is usp_GetLLMOptionByUserOrPersona. It uses a user's RoleId to find the matching persona and active LLM configuration.

Stored Procedure How It Uses Roles Relationship Path
usp_GetLLMOptionByUserOrPersona When called by UserId, it reads Users.RoleId, maps the role to a persona, then finds the active LLM option for that persona. Users.RoleId -> Roles.RoleId -> PersonaMapper.RoleId -> PersonaType -> LLMMapper -> LLMOption

Sample Join Queries

Use these examples when checking which users have which roles, or when tracing how a role resolves into an LLM persona.

-- Users with their auth roles
SELECT
    u.UserId,
    u.Email,
    r.RoleId,
    r.RoleName,
    r.IsActive AS RoleIsActive
FROM dbo.Users u
INNER JOIN dbo.Roles r
    ON r.RoleId = u.RoleId
ORDER BY r.OrderId, u.UserId;
-- Role to LLM persona mapping
SELECT
    r.RoleId,
    r.RoleName,
    pm.PersonaMapperId,
    pt.TypeId AS PersonaTypeId,
    pt.Name AS PersonaName,
    pm.IsDefault,
    pm.IsActive
FROM dbo.Roles r
INNER JOIN dbo.PersonaMapper pm
    ON pm.RoleId = r.RoleId
INNER JOIN dbo.PersonaType pt
    ON pt.TypeId = pm.PersonaTypeId
ORDER BY r.OrderId, pm.IsDefault DESC;
-- Full path from user role to selected LLM option
SELECT
    u.UserId,
    u.Email,
    r.RoleName,
    pt.Name AS PersonaName,
    lm.ModelRole,
    lo.Provider,
    lo.Model,
    lo.Name AS LLMOptionName,
    lo.BaseUrl
FROM dbo.Users u
INNER JOIN dbo.Roles r
    ON r.RoleId = u.RoleId
INNER JOIN dbo.PersonaMapper pm
    ON pm.RoleId = r.RoleId
    AND pm.IsDefault = 1
    AND pm.IsActive = 1
INNER JOIN dbo.PersonaType pt
    ON pt.TypeId = pm.PersonaTypeId
INNER JOIN dbo.LLMMapper lm
    ON lm.PersonaTypeId = pt.TypeId
    AND lm.IsActive = 1
INNER JOIN dbo.LLMOption lo
    ON lo.LLMOptionId = lm.LLMOptionId
    AND lo.IsActive = 1
ORDER BY u.UserId, lm.ModelRole;

Stored Procedure

usp_GetLLMOptionByUserOrPersona reads LLMOption through LLMMapper.LLMOptionId to return the model configuration selected for a role/persona request.

Sample Queries

-- Active LLM options
SELECT
    LLMOptionId,
    Name,
    Provider,
    Model,
    Version,
    IsActive
FROM dbo.LLMOption
WHERE IsActive = 1
ORDER BY LLMOptionId;
-- Update an LLM option description
UPDATE dbo.LLMOption
SET
    Description = N'Doctor executor model option',
    UpdatedDate = SYSUTCDATETIME()
WHERE Name = N'HCDocExecutor';

LLMMapper Table

Stored Procedure

usp_GetLLMOptionByUserOrPersona orders active mapper rows by IsDefault DESC and Priority ASC to choose the best active LLM mapping for a persona and optional model role.

Sample Queries

-- LLM mapping with persona and model option names
SELECT
    lm.LLMMapperId,
    pt.Name AS PersonaName,
    lm.ModelRole,
    lm.MapType,
    lo.Name AS LLMOptionName,
    lo.Provider,
    lo.Model,
    lm.IsDefault,
    lm.Priority,
    lm.IsActive
FROM dbo.LLMMapper lm
INNER JOIN dbo.PersonaType pt
    ON pt.TypeId = lm.PersonaTypeId
INNER JOIN dbo.LLMOption lo
    ON lo.LLMOptionId = lm.LLMOptionId
ORDER BY pt.TypeId, lm.ModelRole, lm.Priority;
-- Deactivate one mapper without deleting history references
UPDATE dbo.LLMMapper
SET
    IsActive = 0,
    UpdatedDate = SYSUTCDATETIME()
WHERE LLMMapperId = 6;

Dev SQL Agent Ownership

The Dev SQL Agent owns the database side of the project. This role designs and manages the data storage for the healthcare platform.

  • Owns: hc_data_source/hc_sql/ and data model documentation.
  • Maintains: schemas, SQL migration scripts, stored procedures, queries, and database validation work.
  • Focus: data integrity, relationships, query performance, healthcare domain models, ORM alignment, and Graphify data requirements.
  • Works with: Architect, Dev .NET, Dev FastAPI, Dev BigData, and Product Owner.
