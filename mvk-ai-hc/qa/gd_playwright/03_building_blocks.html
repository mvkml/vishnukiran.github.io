Building Blocks

Plain Tests are organized by which persona they belong to and whether that persona has a real backend yet — a structure that makes it obvious, just from the folder layout, which parts of the app are genuinely wired up.
hc_qa/web/aihcweb/ ├── playwright.config.ts ← baseURL http://localhost:4200, single worker, serial ├── tests/ │ ├── admin-user/ ← Admin persona (mock backend, AdminAuthMockService) │ │ ├── admin-login/admin-login.spec.ts │ │ └── admin-signup/admin-signup.spec.ts │ └── site-user/ ← Doctor/Patient (real HC.AI.Identity.Api) │ ├── doctor-user/{login,signup}/*.spec.ts │ └── patient-user/{login,signup,chat}/*.spec.ts └── fixtures/ ├── auth.ts ← seedUser() — creates a real account via the Identity API └── admin-auth.ts ← seedAdminAccount() — writes directly into localStorage

playwright.config.ts runs everything serially, single worker (workers: 1, fullyParallel: false) — deliberate, since several tests seed real accounts against a shared backend and would conflict if run in parallel. No multi-browser matrix is configured, so tests run in Chromium only.

fixtures/auth.ts's seedUser() posts directly to HC.AI.Identity.Api's signup endpoint to pre-create a real test account, bypassing the UI — a normal pattern for keeping tests fast while still exercising a real backend for the actual scenario under test.
