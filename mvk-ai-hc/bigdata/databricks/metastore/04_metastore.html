Azure Databricks / Metastore

Metastore

Definition A metastore is the top-level container in Unity Catalog. Catalogs are created inside a metastore, and the metastore manages metadata, permissions, and governance for those data assets.

A metastore in Databricks is the central place where Unity Catalog stores metadata about your data assets.
Registry Think of it as the registry for:
  • Catalogs
  • Schemas
  • Tables
  • Views
  • Volumes
  • Permissions
  • Storage locations
Important Point It does not usually store the data itself. Instead, it tracks where the data lives and who can access it.
Storage Root Issue Your error means Databricks is trying to create a catalog that needs a managed storage location, but the metastore's configured storage root URL either does not exist, is not configured, or cannot be accessed.
Unity Catalog Hierarchy 
Metastore
  -> Catalog
      -> Schema
          -> Table
Example 
main.sales.orders
  • main is the catalog
  • sales is the schema
  • orders is the table
Options For this specific issue, you have two choices:
  1. Use Default Storage from the Databricks UI. Since your account says Default Storage is enabled, create the catalog through the Databricks UI and choose Default Storage.
  2. Provide a managed storage location manually.
CREATE CATALOG myCatalog
MANAGED LOCATION 's3://my-bucket/path/';
CREATE CATALOG myCatalog
MANAGED LOCATION 'abfss://container@storageaccount.dfs.core.windows.net/path/';
Summary In short: the metastore is the Unity Catalog metadata container, and the metastore storage root is the cloud storage path Databricks uses for managed data when you do not provide a catalog-specific location.
How To Create Metastore You create the metastore in the Databricks Account Console, not inside a notebook or SQL editor.
  1. Go to Databricks Account Console
  2. Open Catalog
  3. Click Create metastore
  4. Choose the region
  5. Attach/link the workspace to that metastore

The most important rule: the metastore must be in the same cloud region as your Databricks workspace. Databricks says a metastore is scoped to a single cloud region, and you typically need one metastore per region where your organization has workspaces.

See Databricks docs: Create a Unity Catalog metastore and Unity Catalog securable objects.

For your catalog error, you probably do not need to create a new metastore if one already exists. Instead, create the catalog using one of these: 

CREATE CATALOG my_catalog;

using Default Storage from the UI, or:

CREATE CATALOG my_catalog
MANAGED LOCATION 'abfss://container@storageaccount.dfs.core.windows.net/path/';

for Azure, or:

CREATE CATALOG my_catalog
MANAGED LOCATION 's3://bucket/path/';

Quick check: in your Databricks workspace, look at the workspace URL or admin settings to find the region. Then create/attach the metastore in that same region.
