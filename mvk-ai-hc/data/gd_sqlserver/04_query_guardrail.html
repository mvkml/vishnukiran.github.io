The Query-Guardrail Procedure

Plain When a Doctor asks the AI assistant a question that needs real patient data, the language model never gets to write SQL itself. It describes the shape of the data it wants, and a single stored procedure — usp_ExecuteHealthcareQuery — decides whether that shape is even allowed before touching the database.

What the procedure actually does

hc_data_source/hc_sql/procedures/usp_ExecuteHealthcareQuery.sql takes a root table, an optional single join, a set of columns, up to 5 filters, an order-by, and a record limit — then, step by step:

  1. Clamps the requested record count server-side (default 10, hard ceiling 50) — the caller's number is never trusted as final.
  2. Checks the requested root table against TableWhitelist for that persona; rejects with an error if it isn't listed.
  3. Resolves any join only through JoinWhitelist — never from whatever the caller supplied directly.
  4. Resolves selectable columns through ColumnWhitelist.
  5. Builds the FROM/JOIN clause using only whitelist-sourced identifiers, quoted via QUOTENAME.
  6. Builds filters (equals/contains/greater-than/less-than) — filter columns are whitelist-checked, and filter values are always bound as parameters to sp_executesql, never concatenated into the SQL text.
  7. Optionally scopes results to the requesting doctor's own patients.
  8. Executes, then writes one row to QueryAuditLog for every execution — a permanent record of what was asked, by whom, and how many rows came back.
EXEC dbo.usp_ExecuteHealthcareQuery @Persona = 'Doctor', @RootTable = 'Patients', @JoinTable = 'Encounters', @SelectColumnsCsv = 'FirstName,LastName,EncounterDate', @FiltersJson = '[{"column":"LastName","op":"contains","value":"Smith"}]', @MaxRecords = 10, @ProviderId = 42, @ExecutedBy = 'doctor@example.com';

This is the concrete, database-side enforcement of a design rule stated in the project's own AI assistant design document: the LLM never generates raw SQL — only a structured request shape, validated before it ever reaches the database.
