Azure Administration / Subscription

Azure Subscription

Definition An Azure subscription is a container used to create, manage, secure, and bill Azure resources.

Where It Fits

A subscription belongs to a Microsoft Entra ID tenant and contains resource groups and Azure resources. 
Microsoft Entra ID Tenant
  -> Azure Subscription
      -> Resource Groups
          -> Azure Resources

What A Subscription Controls

A subscription defines where Azure resources live and how they are managed. It mainly controls:
  • Billing and cost tracking
  • Resource ownership
  • Access control through Azure RBAC
  • Usage limits and quotas
  • Governance policies
  • Environment separation such as dev, test, and production

Multiple Subscriptions

A single Microsoft Entra ID tenant can have multiple subscriptions. 
CarePlus Health Tenant
  -> Dev Subscription
  -> Test Subscription
  -> Production Subscription
Multiple subscriptions are commonly used to separate environments, departments, projects, cost centers, security boundaries, and compliance-sensitive workloads.

Resource Group Relationship

A resource group always belongs to one subscription. 
One subscription -> many resource groups
One resource group -> one subscription only

Access And Permissions

A subscription does not automatically give access to its resources. Access is still controlled by identity and permissions. 
Access = Authentication + Authorization

Automation Identity

For service principals or automation, these values are commonly involved: 
Tenant ID                  = where to authenticate
Client ID                  = which application identity
Client secret/certificate  = proof of identity
Subscription ID            = which Azure subscription to operate on
RBAC role                  = what actions are allowed

Same Subscription And Cross-Subscription Access

Resources do not automatically access each other just because they are in the same subscription or tenant. The accessing application or service must have an identity and the correct permissions.

Databricks Example

If Azure Databricks needs to access a Storage Account, it needs a managed identity, service principal, SAS token, or another supported authentication method with proper permissions such as Storage Blob Data Contributor. 
Subscription A
  -> Storage Account

Subscription B
  -> Databricks
Databricks in Subscription B can access a Storage Account in Subscription A only if the required identity has permissions on the Storage Account. If both subscriptions are under the same tenant, this is simpler. If they are under different tenants, cross-tenant configuration is required.

Article Summary

An Azure subscription is the main Azure boundary for billing, resource management, access control, governance, and quotas. It sits under a Microsoft Entra ID tenant and contains resource groups and Azure resources. A tenant can have multiple subscriptions, and access to resources inside a subscription depends on identity, RBAC permissions, and resource-level security settings.
