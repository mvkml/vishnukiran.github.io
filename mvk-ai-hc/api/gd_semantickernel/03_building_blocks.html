Building Blocks

Plain One small factory class is responsible for building a fresh, ready-to-use connection to the language model on every request, using whichever model/provider settings apply to that request.

The Kernel factory

HC.AI.MAPI.Semantic/Factory/KernalFactory.cs, in full:

public class KernalFactory : IKernalFactory
{
    public Kernel CreateKernel(LLMOptionItem llmOptions)
    {
        switch (llmOptions.Provider)
        {
            default:
                return Kernel.CreateBuilder()
            .AddOllamaChatCompletion(modelId: llmOptions.Model, endpoint: new Uri(llmOptions.BaseUrl))
            .Build();
        }
    }
}

The model ID and endpoint URL come from the LLMOptionItem parameter — dynamic, not hardcoded — which is exactly the object the EF Core and ASP.NET Core sections describe being resolved per persona. The switch on Provider has only a default case today, so in practice this is Ollama-only right now, but the shape is already built to add a real branch for another provider later without changing every caller.

One inconsistency worth flagging: a second, separate place in the codebase (DoctorPromptProvider, in the Prompt Layer) builds its own Kernel directly from static configuration rather than going through KernalFactory — used only by an older demo endpoint, not the current locked Doctor flow, but it means two Kernel construction paths exist side by side today.
