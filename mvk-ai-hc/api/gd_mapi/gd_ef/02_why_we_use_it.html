Why We Use It

Plain Every backend API in this project that talks to a database (HC.AI.Identity.Api today, HC.AI.MAPI and AI.HealthCare.Patient.API following the same pattern) needs a consistent, reliable way to read/write records — users, roles, documents, and (in HC.AI.MAPI's case) the persona/LLM-configuration tables discussed elsewhere in this project. EF Core gives every API the same approach instead of each one inventing its own data-access code.
Technical This project standardizes on EF Core 8 with the SQL Server provider across its .NET APIs, using a code-first, migration-driven workflow — the C# entity classes are the source of truth, and schema changes are captured as versioned migration files (not hand-written ALTER TABLE scripts run ad hoc). This keeps schema history in source control alongside the code that depends on it.
