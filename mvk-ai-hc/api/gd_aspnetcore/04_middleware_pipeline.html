Middleware Pipeline

Plain Every request passes through a fixed sequence of checks before it reaches business logic — but not every API in this project needs every check, since not every API has the same security requirements yet.

The common baseline order, shared by every API:

UseHttpsRedirection() UseAuthentication() // where present UseAuthorization() MapControllers()

Where the four APIs actually differ — represented honestly rather than as one uniform pattern:

APIAuthenticationCORSAnything unique
HC.AI.Identity.Api JWT Bearer (issues + validates) AllowAngularDev — localhost:4201 —
HC.AI.MAPI JWT Bearer (validates tokens issued by Identity.Api) None configured Custom CurrentUserMiddleware between Authentication and Authorization, populating request context from claims
AI.HealthCare.Patient.API None — no AddAuthentication at all None configured —
HC.AI.Admin.API JWT Bearer localhost:4200 (different origin than Identity.Api's) —
Plain In short: identity and admin enforce login end-to-end; the AI assistant validates a token if one is sent but doesn't require it yet (see the Identity & Authentication section's Current Status topic for that gap); patient records currently has no authentication layer at all. Stated plainly here rather than glossed over, so it's an explicit, visible item to prioritize rather than a surprise found later.
